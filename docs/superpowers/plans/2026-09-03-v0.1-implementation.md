# v0.1 implementation plan

Approved design: `../specs/2026-09-03-spec-to-pytest-v0.1-design.md`.
Status: in progress. Checked items require actual implementation and verification evidence.
No item authorizes remote repository creation, license selection, release publication or posting.

Work sequentially in this independent repository. For each behavior change: add the failing
regression, implement the minimum change, run focused tests, then the wider relevant suite.
Keep local execution artifacts ignored. Record failed experiments rather than reporting guesses.

## P1. Independent intake and reproducible environment (A01–A03)

- [x] Copy the allowlisted application/framework/core tests, not old Git history, environment,
  generated output or reports. Do not migrate trading, WireMock, Jenkins or Docker.
- [ ] Rename metadata, add safe ignores and contributor rules. Record migration provenance.
- [ ] Resolve `uv.lock`; install with frozen dependencies. Replace invalid legacy lock workflow.
- [ ] Verify the original directory is unchanged. Record interpreter and dependency versions.

Files: `pyproject.toml`, `uv.lock`, `.gitignore`, `AGENTS.md`, `docs/reference/provenance.md`.
Checks: `uv sync --frozen --extra test --extra dev`, `uv run ruff check .`.

## P2. Local application's data, media and sessions (A04, A05, A07)

- [ ] Add an application factory and SQLite repository scoped to an explicit data directory.
- [ ] Add real PNG/JPEG validation, 2 MiB/20 MP limits, metadata stripping and safe resource paths.
- [ ] Replace username cookies with random expiring sessions; revoke on logout.
- [ ] Check browser mutation origins; require an ephemeral control credential for test-only reset.
- [ ] Preserve core business semantics and dashboard compatibility. Test the comment-count bug.
- [ ] Test application restart, isolated instances, failed uploads, traversal, forged sessions,
  trim-before-length rules, anonymous access, likes and comments.

Files: `practice_app/{main,repository,media,settings,models}.py`, existing HTML/JS,
`tests/unit/test_{practice_app,community_app,media,repository}.py`, `tests/api/`.
Checks: focused tests before browser integration; repeat startup against the same database.

## P3. Owned service lifecycle and baseline execution (A02–A05)

- [ ] Start only owned loopback services; match port, application ID, version, instance and bug mode.
- [ ] Reject occupied ports and multiple workers. Stop only child processes owned by the runner.
- [ ] Add per-case clean fixtures and separate contexts. Never expose reset credentials in reports.
- [ ] Preserve raw exit status and per-run reports; capture startup/cleanup failures explicitly.
- [ ] Run core API/UI suites in normal order, reverse order and individually.

Files: `framework/runtime/`, `scripts/run_local.py`, `framework/plugins/`, API client,
`tests/unit/test_runtime.py`, `tests/ui/`. Checks: `make baseline`, process-level regression tests.

## P4. v2 plans and data contracts (A06, A07)

- [ ] Unique plan `case_id`, separate CSV `data_id`, rule references and explicit source metadata.
- [ ] Reject empty/duplicate/mixed-scenario plans and invalid/nonlocal artifact references.
- [ ] Freeze input snapshots and hashes. Export schemas mechanically from models.
- [ ] Use synthetic contract fixtures; never depend on a user's mutable knowledge database.

Files: `framework/ai/contracts.py`, `scripts/validate_ai_assets.py`, `mana/schemas/`,
`tests/unit/test_ai_contracts.py`. Checks: valid and invalid fixtures, stale-schema check.

## P5. Execution evidence and reconciliation (A06–A08)

- [ ] Collect explicit case/node mapping; emit setup/call/teardown events and completion records.
- [ ] Cross-check plan, collection, events, JUnit and process result. Unknown/missing data blocks green.
- [ ] Preserve distinct run and attempt IDs; never clean previous Allure/trace output.
- [ ] Generate manifests and summaries from machine evidence with relative paths and reason codes.
- [ ] Test bad XML, interruption, zero collection, missing/extra/duplicate cases, skips/xfails,
  teardown errors, absent evidence and paths escaping the run directory.

Files: `framework/ai/{execution,reconcile,paths}.py`, result plugin, prepare/finalise scripts,
`tests/unit/test_{execution,reconcile}.py`. Checks include real pytest subprocesses, not only fake XML.

## P6. Repairs, approved replay and step knowledge (A08, A09, A11)

- [ ] Freeze protected inputs and parsed assertions; reject skips, changed expectations or >3 repairs.
- [ ] Save patches, before/after hashes and per-attempt sources. Require final full-suite acceptance.
- [ ] Stage approved examples into an isolated generated directory without inventing a new AI source.
- [ ] Promote successful exploration candidates only with linked passing execution evidence.
- [ ] Test lock contention, stale knowledge, failed candidates and immutable old attempts.

Files: `framework/ai/{integrity,steps}.py`, replay entry point, `examples/approved/`, integrity tests.
Checks: healthy replay three times; separate known-defect run with the expected real inner failure.

## P9. CI, privacy and release gate (A03, A12–A14)

- [ ] Read-only, pinned GitHub Actions for lint/types/unit, API/Chromium and redacted secret scanning.
- [ ] Scan all candidate files/history and exported artifacts; manually inspect binary media.
- [ ] Do not attach raw browser state or traces to public CI by default; use a safe export allowlist.
- [ ] Maintain an acceptance ledger recording command, environment, result and unavailable checks.
- [ ] Ask separately before choosing LICENSE, creating/pushing the remote and publishing a release.
- [ ] Only claim GitHub CI support after a real run there; label local-only checks accurately.

Completion means all applicable A01–A14 evidence is recorded and release approvals are resolved.
An incomplete host run, unavailable scanner or missing remote CI result remains explicit, not silently waived.
